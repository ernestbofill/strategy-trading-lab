Decisions that outlive a PR, and why. One dated line each, newest first, with the PR number. The PR has the detail.

- 2026-10-27 · Advanced settings match the POC's tunable numeric rules for every template (Ernest: "the strategy behaviour and settings should match"), grouped by what they decide (candidate, buy signal, milestones, pace) and explained, since it's the one screen that may be technical. *Dip in winners* keeps its two extra averages (trend and floor). Review's rules show the chosen values. (#74)
- 2026-10-25 · *Your AI's top picks* is built, with Claude's assumptions where the spec was open (Ernest gave full autonomy: "be creative, it's experimental"): shared AI rounds have no key to the user and keep only their day, and the user's own round notes its shared copy, so they aren't truly anonymous and turning sharing off removes them (changed after the code review found the first "can't be traced" claim false); edited prompts are kept with their flag; the suggested prompt v1 and its criteria are Claude's, written by the API alone so every screen shows the same words, and only the instructions are editable (the date line, answer table and stock list stay the app's so the answer can be read); the reader takes a Markdown table or JSON and finds stocks by symbol or name. (#70)
- 2026-10-25 · The AI round's screens, emails and messages are in English and Catalan, but the prompt itself is the same English text for every user (the user journey: "the same for every user, apart from their stock list and the sources"), so rounds compare across users and AIs; the reader also accepts Catalan table headers. (#70)
- 2026-10-25 · AI rounds: due on the start day, then every `EveryWeeks` (2 to 6) after the last due date; open 7 days, then skipped. Top N (1 to 3) get a step each; a stock with all its steps passes its turn to the next score. A round's signals are dated the last finished session and trade at the first open after the round was run (no buying at an open already passed). A live AI signal is missed when the next round is due. (#70)
- 2026-10-25 · Catalan translations and language selection: Frontend messages catalogued in English and Catalan (`frontend/src/i18n/messages/`), selected explicitly by the user (English by default, never guessed from the browser), stored per device in localStorage and synced with user account locale on login (`POST /account/locale`). API requests attach `Accept-Language: currentLocale()`, and the backend returns localized validation messages, account emails, and signal notifications. Disclaimers strictly adhere to fixed translations in `docs/glossary-ca.md`.
- 2026-10-25 · Strategy tuning on running strategies: "Tune the settings" on /strategies/:id opens /strategies/:id/settings with the same controls and bounds as the template's Advanced settings, updating strategy.params via PUT /strategies/:id/settings without affecting past signals or trades. (#63)
- 2026-10-25 · Your trades (Signals and trades): "Signals and trades" section on the strategy page shows every signal and trade in date order (newest first). Live mode allows inline trade editing (date, price, amount/shares, fee, fxRate), soft-deletion (`deleted_at`), and "Log a trade by hand" on active stocks of the strategy. Engine invariance is preserved: manual trades, edits and deletes affect only the user's positions and results (`You`), leaving the rules' own position (`The rules alone`) and signal trades unchanged. All historical signals are preserved in `signalHistory` for regulatory compliance (design rule 7). (#61)
- 2026-10-25 · In-app feedback: any authenticated user with a confirmed email may select text on any screen to submit feedback (bug, idea, note, feature); only the owner reviews, edits, closes/reopens and deletes items on /admin and /feedback, and the Account page links to /admin for the owner. (#48)

- 2026-10-23 · The daily check never rewrites the past: a day already evaluated gets no new signal if a setting, the budget or the price history changes later (no back-dated signals or trades); a stock added to a running strategy is evaluated from the day it was added; and a signal is only made while its step still fits in the budget (the budget counts every signal's step amount). Recommended by the review of #45; say if you want it otherwise. (#45)
- 2026-10-23 · The daily check runs right after each price refresh and evaluates up to the last finished US session (16:30 New York, weekdays; a holiday simply has no bar). A strategy starts fresh on its start day, like the POC's backtest. A signal's window is open while the buy conditions hold; a live signal still waiting when it closes is `missed`. A simulation signal is confirmed when created. Each signal's trade is made at the next trading day's open, with the tested fee (0.2% + 1) and the day's rate. (#45)
- 2026-10-23 · The engine is pure code over price bars (no database) and is checked against the POC: golden files hold the POC's status, step and signal days on real prices, and a test must match them every day. The rules' own position is the POC backtest's: a signal on day D is bought at D+1's open whatever the user does, so a buy window gives one step, the cooldown counts from that fill, and a window that stays open gives no second step.
